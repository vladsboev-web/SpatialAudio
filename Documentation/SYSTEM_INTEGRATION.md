# 🍏 Интеграция с macOS: CoreAudio, BlackHole и Безопасность (TCC)

В данном документе описано взаимодействие SpatialAudio с системными подсистемами macOS: маршрутизацией звука CoreAudio, виртуальным драйвером BlackHole, связкой ключей и механизмом разрешений TCC.

---

## 1. Виртуальный аудиодрайвер BlackHole 2ch

### Зачем нужен драйвер?
macOS по соображениям безопасности не позволяет обычным пользовательским приложениям перехватывать глобальный системный звук «напрямую» из ядра без виртуального драйвера или расширения ядра (kext/AudioServerPlugIn).

### Принцип работы:
- **BlackHole** — открытый драйвер с нулевой задержкой (`AudioServerPlugIn`), создающий двустороннее виртуальное устройство.
- Любой звук, отправленный приложениями macOS в выходной канал BlackHole, мгновенно становится доступен для захвата на входном канале BlackHole.
- SpatialAudio назначает BlackHole устройством вывода системы по умолчанию, захватывает этот поток через AUHAL, накладывает пространственную обработку Apple HRTFHQ и выводит результат на физические наушники.

## 2. Архитектура системного переключения звука

### 2.1. Слушатели CoreAudio (Hardware Listeners)
При старте `AudioCoordinator` регистрирует слушатели системных событий:
```swift
// 1. Изменение списка оборудования (подключение/отключение наушников)
kAudioHardwarePropertyDevices

// 2. Смена системного устройства вывода по умолчанию пользователем
kAudioHardwarePropertyDefaultOutputDevice
```

### 2.2. Сценарий: Пользователь переключает звук в Центре управления macOS

```
Пользователь кликает в системном меню звука:
              │
              ├──► [ Выбраны Динамики / Другие наушники ]
              │          │
              │          ▼
              │    1. Фиксируем выбранный физический выход:
              │       selectedOutputDeviceID = currentDefault
              │       savedSystemDefaultOutputDeviceID = currentDefault
              │    2. Вызываем pausePipeline() (остановка AUHAL и AVAudioEngine)
              │    3. Звук macOS идет напрямую без пространственной обработки
              │    4. Нагрузка на процессор = 0%
              │
              └──► [ Выбран BlackHole 2ch (вариант SpatialAudio) ]
                         │
                         ▼
                   1. Размутируем и выставляем громкость BlackHole = 100%
                   2. Стабилизационная пауза 300 мс (браузеры переводят потоки)
                   3. Запуск пайплайна: startPipeline(routeSystemAudio: false)
                   4. Обработанный 3D-звук сразу поступает в активные наушники!
```

### 2.3. Горячее подключение Bluetooth-наушников
При включении наушников (например, `UGREEN-BT505`):
1. CoreAudio отправляет событие `kAudioHardwarePropertyDevices`.
2. `handleHardwareDevicesChanged()` вычисляет разницу в списке устройств:
   ```swift
   let newlyConnectedBT = newDevices.first { ($0.isBluetooth || $0.isHeadphones) && $0.hasOutput }
   ```
3. Приложение автоматически переключает свой выходной тракт на новые наушники без прерывания воспроизведения.

## 3. Механизм безопасности macOS (TCC) и цифровая подпись

### 3.1. Почему macOS запрашивает доступ к микрофону?
В macOS захват звука через компонент `kAudioUnitSubType_HALOutput` с флагом `EnableIO` на шине 1 относится к категории конфиденциальности **Microphone** (`kTCCServiceMicrophone`), даже если захват производится не с физического микрофона, а с виртуального драйвера BlackHole.

### 3.2. Проблема исчезающих разрешений при Ad-Hoc подписи
- При стандартной ad-hoc подписи (`codesign -s -`) правило доверия создается на основе хэша бинарного файла (`cdhash`).
- При каждой пересборке хэш изменяется. macOS считает приложение неизвестной новой программой и сбрасывает разрешение.
- При запуске из папки iCloud Drive срабатывает механизм **App Translocation** (запуск из временной случайной папки `/private/var/folders/...`), что делает путь к приложению нестабильным.

### 3.3. Решение: Локальный сертификат разработчика
В системной связке ключей `login.keychain` создан постоянный локальный сертификат:
- **Имя**: `SpatialAudio Local`
- **Назначение**: Code Signing (1.3.6.1.5.5.7.3.3)
- **Срок действия**: 10 лет

В скрипте сборки `build_app.sh`:
```bash
# Подписание стабильным сертификатом
codesign --force --deep -s "SpatialAudio Local" "$APP_DIR"

# Установка в постоянный системный путь
rm -rf "/Applications/SpatialAudio.app"
cp -R "$APP_DIR" "/Applications/SpatialAudio.app"
xattr -cr "/Applications/SpatialAudio.app"
```

### Результат:
Правило доверия (*Designated Requirement*) зафиксировано навсегда:
`designated => identifier "com.user.SpatialAudio" and certificate leaf = H"291270a4dfb52718..."`
macOS запоминает выданное разрешение при первом нажатии «OK» и **больше никогда не запрашивает его повторно**.
